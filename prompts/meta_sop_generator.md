# 故实巡礼 — AI 内容生产工作流 Prompt v2

> **定位**：这不是一份人工操作手册，而是一份喂给 AI Agent 的**自动化执行指令**。
> AI 负责：选题策划、书籍分析、地点提取、数据结构化、全书元数据、故事撰写、质量审查。
> 代码/人工负责：文本分片、地理编码 API 调用、最终内容包构建。
>
> **目标**：一次对话，产出一部作品的完整结构化地点数据，可直接进入地理编码环节。
>
> **v2 更新（2026-03）**：
> - 新增全书元数据层（book_info / characters / parts）
> - 新增角色统一系统（解决同一人物多名称问题）
> - 新增篇章(Part)划分（解决多篇章作品的章节编号混乱）
> - 新增打卡可行性(visitability)字段
> - 地址精度要求提升到街道/建筑级别
> - REVIEW 增加低价值 passing 地点降噪

---

## 使用方法

1. 复制下方 `<<<PROMPT BEGIN>>>` 到 `<<<PROMPT END>>>` 之间的全部内容
2. 替换 `{{INPUT_MODE}}` 为以下之一：
   - **模式 A — AI 自主选题**：`请你自主选择一部适合地理化的作品，并执行完整工作流。`
   - **模式 B — 指定作品+原文**：`请处理以下作品：《书名》，作者：XXX。`（后面附原文或章节分片）
   - **模式 C — 指定作品无原文**：`请基于你的知识处理：《书名》，作者：XXX。`
   - **模式 D — 批量选题**：`请生成 10 部适合地理化的作品选题，并为 S 级作品执行完整工作流。`
3. 如有原文/分片文本，拼接在 `{{TEXT_INPUT}}` 处（无则留空）
4. 发送给 LLM（推荐 Claude / GPT-4）

╔═════════════════════════════════════════╗
║ 阶段 0 ── 选题评估                      ║
╚═════════════════════════════════════════╝

目的：判断目标作品是否值得被地理化。

步骤 (a) 确定作品基本信息：
  - 作品名称、作者、类型
  - 时代背景、地理范围、估算总字数

步骤 (b) 量化评估：
  - 地点密度指数 = 预估地点数 ÷ 总万字数
  - 现实可达率 = 可编码数 ÷ 总提取数
  - 路线形态（线状/网状/点状）

步骤 (c) 定级：S/A/B/C

步骤 (d) 输出评估报告


╔═════════════════════════════════════════╗
║ 阶段 1 ── 地点提取                      ║
╚═════════════════════════════════════════╝

目的：从文本（或你的知识）中提取所有真实、可巡礼的地理位置。

▎规则 1 — 精确性
  - 只提取有具体兴趣点的地点
  - 忽略通用类别名称和模糊范围

▎规则 2 — 核查与补充
  - 核实真实性，补充完整结构化地址
  - ⚠️ 地址必须精确到街道/建筑级别

▎规则 3 — 角色统一（v2 新增）
  - characters 使用角色真名，不用代词
  - 同一人物全局使用一个名称

▎规则 4 — 原著章节映射（v2 新增）
  - 标注 original_chapter（原书章节名）

▎规则 5 — 虚构过滤
  - 虚构地名标注 fictional_suspect: true

▎输出格式（JSON 数组）：
  [
    {
      "title": "地点名称",
      "address": "国家-省-市-区-具体地点",
      "story": ["情节描述"],
      "source_evidence": "原文引用",
      "original_chapter": "原著章节名",
      "event_level": "major|minor|passing",
      "characters": ["角色真名"],
      "fictional_suspect": false
    }
  ]

║ 阶段 2 ── 结构化与富化                  ║
╚═════════════════════════════════════════╝

目的：将粗提取数据转化为富含信息的结构化记录 + 故事模式。

▎第一步：基础结构化
  (a) Synopsis ≤80字
  (b) 时空语境 temporal_context
  (c) 叙事语境 narrative_context（角色名统一）
  (d) 文化标签 cultural_tags
  (e) 原著章节映射 original_chapter
  (f) 打卡可行性 visitability（v2 新增）：

      note / current_name

▎第二步：角色统一（v2 新增）
  同一人物全局使用完全相同的名称

▎第三步：篇章(Part)划分（v2 新增）
  part_id / part_title，chapter_title 在 part 内编号

▎第四步：故事排序
  orderIndex 从 1 递增

▎第五步：故事模式（Story Mode）
  🎯 新读者通过阅读所有 story_mode 就能理解整个故事
  - 人物首次出场自然交代身份
  - part 切换处有背景引入
  - 跨 part 的 transition_to 暗示篇章转换

▎第六步：地址精确化
  必须到街道/建筑级别
